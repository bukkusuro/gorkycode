# Развёртывание ВОКСА на Ubuntu

Основной адрес приложения: https://voxacode.online/ (перенаправляет на `/VoiceTask/`).
HTTP и `www` перенаправляются на основной HTTPS-домен.
На домене установлен доверенный сертификат Let's Encrypt.
Внутренний адрес — https://10.40.50.185/VoiceTask/;
на внутреннем адресе используется самоподписанный сертификат.

## Домен voxacode.online

На общем прокси `10.40.50.200` установлен HTTPS-конфиг
`/etc/nginx/sites-available/voxacode.online` и ссылка в `sites-enabled`.
Он передаёт запросы на `https://10.40.50.185`, сохраняя Host и проверяя
сертификат внутреннего сервера по имени `voice`.
Публичная часть сертификата внутреннего сервера находится на прокси в
`/etc/nginx/ssl/voicetask-backend.crt`; при его замене нужно обновить эту копию.

A-записи `@` и `www` в REG.RU указывают на `46.191.157.73`;
изменение подтверждено напрямую на обоих авторитетных DNS-серверах.
Сертификат выпущен 27 октября 2026 года, действует до 25 января 2027 года
и включает `voxacode.online` и `www.voxacode.online`.
Файлы — `/etc/letsencrypt/live/voxacode.online/` на прокси.
Настройка завершена скриптом `~/voxacode-deploy/activate-domain.sh`.

На этом прокси порт 443 занят существующим `stream` с PROXY protocol;
HTTPS-сайты слушают `127.0.0.1:4443 ssl proxy_protocol`.
Поэтому применён отдельный webroot-выпуск сертификата вместо `certbot --nginx`,
который мог бы добавить несовместимый `listen 443 ssl`.
Планировщик `snap.certbot.renew.timer` включён;
для сертификата сохранён hook `nginx -t && systemctl reload nginx`.
Финальная конфигурация — `voxacode.https.conf`, общий прокси — `voxacode.proxy.conf`.
Через внешний IP `46.191.157.73` успешно проверены доверие к сертификату,
перенаправления HTTP/HTTPS и `www`, страница приложения
и API `/VoiceTask/api/health`. `port_in_redirect off` в общем snippet
предотвращает попадание внутреннего порта 4443 в перенаправления.
У отдельных DNS-резолверов некоторое время может сохраняться старый адрес
`95.163.244.138` до истечения кеша.

## Сервер приложения

Приложение находится в `/opt/voicetask/current`, который ссылается на каталог
в `/opt/voicetask/releases`. Общие настройки — `/opt/voicetask/shared/.env`
с правами `600`. Модели и Linux-программа Whisper — в
`/opt/voicetask/shared/speech`; каждый выпуск подключает их через символические ссылки.
Ключ OpenRouter остаётся на сервере и не включается в клиентскую сборку.

Используется Node.js 24.13.1 в `/opt/voicetask/node`.
В чистом каталоге выпуска выполните `npm ci`, `npm run build`, `npm test`
и `npm run test:build` с `/opt/voicetask/node/bin` в `PATH`.
Затем подключите `.env` и `.tools/speech`, переключите `current`
на новый выпуск и выполните `sudo systemctl restart voicetask`.
Старый каталог выпуска можно сохранить для отката.

`voicetask.service` запускает API от пользователя `sdevs` на `127.0.0.1:3000`.
Nginx отдаёт только `dist` и перенаправляет `/VoiceTask/api/` в API.
Конфигурация Nginx — `/etc/nginx/sites-available/voicetask`,
сертификат и закрытый ключ — `/etc/nginx/ssl/voicetask.crt` и `voicetask.key`.
Оба сервиса включены в автозапуск.

Проверка: `systemctl status voicetask nginx`.
Логи API: `sudo journalctl -u voicetask -n 100 --no-pager`.
Проверка API: `curl --cacert /etc/nginx/ssl/voicetask.crt https://10.40.50.185/VoiceTask/api/health`
(для чтения сертификата из этого каталога нужны права администратора).

Linux-программа `whisper-cli` собрана из whisper.cpp v1.8.3 с
`-DGGML_NATIVE=OFF -DGGML_AVX=OFF -DGGML_AVX2=OFF -DGGML_BMI2=OFF -DGGML_FMA=OFF
-DGGML_F16C=OFF -DGGML_OPENMP=ON -DWHISPER_CURL=OFF -DBUILD_SHARED_LIBS=OFF`.
Виртуальный процессор этого сервера не предоставляет AVX/BMI2/FMA/F16C;
эти возможности нужно отключать явно, чтобы избежать SIGILL.
SHA-256 архива исходников v1.8.3:
`870ba21409cdf66697dc4db15ebdb13bc67037d76c7cc63756c81471d8f1731a`.
Бинарный файл установлен в `shared/speech/bin/whisper-cli`;
модель VAD `ggml-silero-v5.1.2.bin` используется та же, что в Windows-версии.
На этом сервере выбрана более лёгкая многоязычная `ggml-base-q5_1.bin`:
Whisper small превышает лимит 90 секунд на виртуальном процессоре без AVX.
Модель задаётся через `WHISPER_MODEL` в сервисе; без переменной остаётся Whisper small.
Число потоков автоматически ограничивается доступными процессорами (не более четырёх).
Base загружена из того же репозитория Hugging Face, ревизия
`5359861c739e955e79d9a303bcbc70fb988958b1`; SHA-256:
`422f1ae452ade6f30a004d7e5c6a43195e4433bc370bf23fac9cc591f01a8898`.

Календарь и настройки хранятся отдельно в каждом браузере. Для переноса прежних
записей на новый адрес используйте экспорт и импорт JSON в настройках приложения.
На сайте используются фоновые уведомления Web Push с серверным расписанием.
Локальные фоновые напоминания Windows сохраняются для запуска через START.cmd.

Ключи VAPID и расписание Web Push находятся в `/opt/voicetask/shared/push`
в файлах `vapid.json` и `state.json` с правами `600`; каталог имеет права `700`.
Сервису разрешена запись только в этот каталог через `ReadWritePaths`.
Каталог сохраняется между выпусками; ключи нельзя пересоздавать при обновлении,
иначе браузерам потребуется новая подписка. Отправка использует существующий HTTPS-прокси.
`/VoiceTask/api/push-reminders` отдаёт только публичный ключ, а изменение расписания
требует отдельного случайного токена браузера. Endpoint подписки и содержимое
напоминаний не записываются в публичные логи. Допустимо до 4 000 напоминаний на браузер.
Разрешение браузера запрашивается по нажатию пользователя; сервер не может выдать его
вместо пользователя. Для теста сначала разрешите уведомления в настройках сайта,
затем нажмите «Проверить уведомление» и закройте вкладку.
Проверка на рабочем домене выполнена в отдельном профиле Chrome:
подписка создана через настройки приложения, тест запланирован, все вкладки
приложения закрыты. Service worker получил и показал уведомление до повторного
открытия сайта. Общие тесты календаря, чата, профиля и мобильного интерфейса прошли.
Отдельно проверена обычная будущая задача календаря с напоминанием за 5 минут:
расписание синхронизировалось через приложение, все вкладки были закрыты,
а уведомление задачи появилось в заданное время до повторного открытия сайта.
Для импортированной базы поддерживаются ID `csv:…` и повторения `csv:…@ГГГГ-ММ-ДД`
как в Web Push, так и в локальных уведомлениях Windows и переходах по уведомлению.
Регрессионная проверка `npm run test:push` использует отдельный профиль Chrome,
полностью загружает базу из 1 000 записей и проверяет уведомление импортированной
задачи при закрытых вкладках. Также проверяется, что ошибка сохранения расписания
не запрашивает уже выданное разрешение повторно и не блокирует тестовую отправку.
Для запуска нужен установленный Chrome и доступ к `10.40.50.200`; путь можно задать
через `CHROME_PATH`. Тест не использует основной профиль браузера.

## Подключение OpenRouter

27 октября проверено: с обоих серверов этот отказ приходит даже на публичный
`GET /api/v1/models` без ключа. С компьютера разработки тот же ключ проходит
проверку, а запрос через тот же middleware и выбранную модель возвращает HTTP 200
с корректной командой.

Позднее 27 октября подключён предоставленный пользователем HTTP-прокси.
С сервера через прокси получены HTTP 200 для списка моделей, проверки ключа
и реального запроса к модели через API приложения. Сохранены прежние ключ,
модель `nvidia/nemotron-3.5-super-vl:free` и провайдер NVIDIA.
По данным панели прокси действует до 1 ноября 2026 года; для непрерывной
работы его нужно продлить или заменить.

Сервис запускает Node.js с `--use-env-proxy` и читает необязательный
`/opt/voicetask/shared/proxy.env`. В нём настроены `HTTPS_PROXY`
и `NO_PROXY=localhost,127.0.0.1,::1`, права файла — `600`.
Для смены прокси обновите этот файл и выполните `sudo systemctl restart voicetask`.
Адреса с паролями и ключи не должны попадать в репозиторий или клиентскую сборку.
После смены требуется проверить реальный POST к `/VoiceTask/api/assistant`,
а не только наличие ключа. Подключение использует HTTPS с проверкой сертификата
OpenRouter внутри HTTP CONNECT-туннеля.

Команды вида `задача Подготовить презентацию; завтра; 14:00` после строгого
разбора выполняются локально, даже если ключ настроен, а OpenRouter недоступен.

# ВОКСА (VoiceTask)

Веб-приложение для планирования задач, встреч и событий с календарём, текстовым помощником и голосовым вводом на русском языке.

**Рабочая версия проекта: [https://voxacode.online/VoiceTask/](https://voxacode.online/VoiceTask/).**

## Возможности

- Календарь по дням, неделям, месяцам и годам; поиск и редактирование записей.
- Задачи, встречи и события, повторения, приоритеты и крайние сроки.
- Управление календарём текстовыми и голосовыми командами с уточнением неоднозначных запросов.
- Предложение плана дня и создание нескольких задач из свободного списка с подтверждением перед сохранением.
- Отчёты о выполнении задач, напоминания и фоновые уведомления Web Push.
- Настройки оформления, экспорт и восстановление календаря в JSON, отмена последних изменений.

Стек: **React 19, TypeScript, Vite, Node.js**, OpenRouter для сложных запросов и **whisper.cpp** для распознавания речи.

## Запуск из репозитория

Понадобятся **Node.js 24 LTS с npm**, Git и современный браузер. Для календаря и обычных текстовых команд ключ API и речевая модель не обязательны.

```bash
git clone https://github.com/bukkusuro/gorkycode.git
cd gorkycode
npm ci
npm run dev
```

Откройте **[http://localhost:5173/VoiceTask/](http://localhost:5173/VoiceTask/)**. Если порт занят, Vite выведет другой адрес в терминале. Остановка — `Ctrl+C`.

Для доступа только с текущего компьютера: `npm run dev -- --host 127.0.0.1`. Vite обслуживает интерфейс и серверные API через плагины; запускать `npm start` отдельно в режиме разработки не требуется.

### ИИ-помощник

Скопируйте `.env.example` в `.env` в корне проекта:

```powershell
# Windows PowerShell
Copy-Item .env.example .env
```

```bash
# Linux / macOS
cp .env.example .env
```

Укажите свой ключ в `.env`:

```dotenv
OPENROUTER_API_KEY=ваш_ключ_OpenRouter
OPENROUTER_MODEL=nvidia/nemotron-3.5-super-vl:free
```

Сервер использует модель и провайдера NVIDIA, настроенные в проекте. Для сложных формулировок, свободных списков дел и перепланирования нужен доступ к OpenRouter; простые команды обрабатываются локально. Ключ остаётся на сервере и не включается в клиентскую сборку. Файл `.env` исключён из Git; в репозиторий входит только пустой пример.

### Голосовой ввод

На **Windows x64** установите компоненты распознавания:

```bash
node scripts/setup-speech.mjs
```

Скрипт загрузит whisper.cpp, многоязычную модель Whisper small и модель VAD в `.tools/speech`, проверив SHA-256 файлов. Для первой установки нужен интернет. Затем запустите `npm run dev`, разрешите браузеру доступ к микрофону и нажмите кнопку записи в чате. Повторное нажатие завершает запись; распознанный текст можно исправить перед отправкой. Длительность записи — до минуты.

Аудио распознаётся на сервере приложения: при локальном запуске — на вашем компьютере, на опубликованном сайте — на сервере сайта. В OpenRouter передаются текст запроса и ограниченный контекст календаря, необходимый для интерпретации.

Для Linux whisper.cpp устанавливается отдельно; пути к бинарному файлу и моделям описаны в [документации развёртывания](deploy/README.md). Автоматический установщик речи использует PowerShell и рассчитан на Windows.

### Запуск из готового Windows-архива

Если в распакованном архиве уже есть `.tools/node.exe` и `node_modules`, можно использовать `START.cmd`; для остановки — `STOP.cmd`. В чистой копии с GitHub эти каталоги отсутствуют: используйте команды установки и запуска выше. Модели речи, зависимости и локальная среда Node.js в Git не включены.

## Как пользоваться

Создайте запись кнопкой в календаре или напишите в чат, например:

- «Создай встречу завтра в 15:00» — помощник уточнит недостающие параметры.
- «Задача Подготовить презентацию; завтра; 14:00» — создание по явно заданным полям.
- «Что у меня завтра?» — просмотр расписания.
- «Перестрой расписание на 2027-06-14» — предложение нового плана с подтверждением.
- «Покажи недельный отчёт по выполнению задач» — статистика по реальным отметкам выполнения.

При первом открытии загружается демонстрационная база из 1 000 записей. Календарь и настройки сохраняются в `localStorage` отдельно для каждого браузера и адреса сайта. Для переноса данных используйте экспорт и импорт JSON в настройках. Отмена доступна для 10 последних изменений текущего сеанса.

Фоновые уведомления включаются в **Настройки → Уведомления**. Web Push требует HTTPS либо localhost, разрешения браузера и серверного каталога `PUSH_REMINDERS_DIR` для ключей и расписания. Для опубликованного сайта предусмотрена серверная конфигурация. Для локального Windows-запуска также доступны системные напоминания через планировщик Windows. Доставка зависит от браузера, работы компьютера в фоне и системных разрешений.

## Проверка и сборка

```bash
npm run typecheck
npm test
npm run build
npm run test:build
```

Браузерные сценарии запускаются отдельно: `npm run test:browser`, `npm run test:planning`, `npm run test:push`. Они требуют работающего приложения и установленного Chrome/Edge; адрес задаётся переменной `VOICETASK_URL`, путь к браузеру — `CHROME_PATH`. Тест Web Push дополнительно требует настроенной серверной доставки и сетевого доступа, указанного в [deploy/README.md](deploy/README.md).

Пример обычного браузерного сценария в PowerShell при работающем `npm run dev`:

```powershell
$env:VOICETASK_URL = 'http://127.0.0.1:5173/VoiceTask/'
npm run test:browser
```

`npm run build` создаёт интерфейс в `dist`. `npm run preview` позволяет просмотреть сборку, но серверные API не запускает. Для полной работы на сервере нужны `npm start` (API, по умолчанию `127.0.0.1:3000`) и веб-сервер, отдающий `dist` по `/VoiceTask/` и проксирующий `/VoiceTask/api/` к API. Пример Nginx и systemd находится в [deploy/README.md](deploy/README.md).

## Самостоятельные решения

- **Гибридная обработка команд.** Простые запросы разбираются локальными правилами, сложные — моделью. Это сокращает задержку, расходы на API и зависимость основных действий от внешнего сервиса.
- **ИИ предлагает структурированные действия.** Ответ модели проверяется по схеме и правилам календаря; свободный текст модели не изменяет данные напрямую. Удаление и применение нового плана требуют подтверждения, неоднозначный выбор — уточнения.
- **Разделение интерпретации и планирования.** ИИ выделяет намерение, сроки и приоритеты, а алгоритм приложения проверяет свободные интервалы и ограничения. Предложенные даты и оценки длительности видны до сохранения.
- **Локальное хранение календаря.** Работа без регистрации и отдельной базы данных упрощает запуск. Экспорт JSON и отмена действий помогают восстановить данные; компромисс — отсутствие автоматической синхронизации устройств.
- **Распознавание речи на собственном сервере.** whisper.cpp не требует отдельного облачного ключа; пользователь проверяет текст до отправки. Компромисс — загрузка моделей и требования к ресурсам сервера.
- **Модульная структура и проверки логики.** Календарь, чат, планирование, хранение и уведомления разделены; серверные API вынесены в `server`. Тесты охватывают даты, повторения, команды, хранение и напоминания.

## Что улучшить при дополнительном времени

1. **Синхронизация устройств:** необязательная авторизация, серверное хранение и разрешение конфликтов при сохранении локального режима.
2. **Качество голосового ввода:** замер точности и задержки на русскоязычных сценариях, более лёгкие модели для слабого оборудования, удобная установка на Linux/macOS.
3. **Интеграции:** импорт и экспорт `.ics`, подключение внешних календарей и обработка конфликтующих встреч.
4. **Надёжность развёртывания:** воспроизводимая установка, CI с проверками на Windows/Linux, мониторинг API и доставки уведомлений.
5. **Удобство и доступность:** дополнительные проверки клавиатурной навигации, экранных дикторов и мобильного интерфейса; понятное управление демонстрационными данными.
6. **Проверка сложных сценариев:** расширить набор примеров неоднозначной речи, смены часовых поясов, переходов на летнее время и плотных расписаний.

| Каталог | Назначение |
| --- | --- |
| `src/calendar` | Представления календаря и поиск |
| `src/chat` | Диалог с помощником и черновики команд |
| `src/planning` | Подбор интервалов и отчёты |
| `src/storage` | Хранение, резервные копии и отмена |
| `src/reminders`, `src/profile`, `src/ui` | Напоминания, профиль и общие элементы интерфейса |

| `scripts` | Установка компонентов и запуск тестов |
| `tests` | Проверки логики, API, сборки и браузерных сценариев |
| `deploy` | Конфигурация и инструкция серверного развёртывания |
